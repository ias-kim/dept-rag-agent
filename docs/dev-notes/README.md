# 개발자 설명 문서 (dev-notes)

코드를 새로 만들거나 동작을 바꾸면 같은 PR에서 이 폴더의 `<주제>.md`를 만들거나 갱신한다. 규칙은 [`AGENTS.md`](../../AGENTS.md) "개발자 설명 문서와 코드 서술".

이 문서는 함수 설명서가 아니다. 다음에 이 코드를 고칠 사람이 **무엇을 건드리면 무엇이 무너지는지** 먼저 알게 하는 것이 목적이다.

## 템플릿

```markdown
# <주제> — 예: 자료 적재(ingest)

> 마지막 갱신: YYYY-MM-DD · 관련 PR/커밋: …

## 1. 핵심 개념
이 모듈이 존재하는 이유와, 이해해야 할 개념 2~4개. 각 개념은 "왜 필요한가"로 시작한다.

## 2. 데이터 흐름
입력 → (변환) → 출력. 단계마다 데이터의 모양(클래스·필드)이 어떻게 바뀌는지.

## 3. 불변 조건과 실패 모드
| 조건 | 깨지면 생기는 문제 | 지키는 장치 |
|---|---|---|
| 예: 전공 조각 검색은 항상 수강 과목 조건을 건다 | 미수강 과목 강의자료가 답변에 섞여 나간다 (권한 사고) | `search.py`의 `where(or_(…))`, `test_mcp_server.py::test_course_code_argument_cannot_widen` |

외부 요인으로 실패할 때(API 오류, 빈 파일, DB 연결 끊김) 무엇이 보이고 무엇이 남는지도 적는다.

## 4. 다음 수정
알고 있는 한계와 예정된 변경(몇 주차, 어떤 계획 문서).

## 5. 업데이트 시 주의점
이 코드를 바꿀 때 같이 바꿔야 하는 곳, 다시 돌려야 하는 명령(`make ingest`, `make eval` 등), 바꾸면 무효가 되는 것(평가 기준선 등).

## (선택) 파일 위치
| 파일 | 역할 한 줄 |
```
