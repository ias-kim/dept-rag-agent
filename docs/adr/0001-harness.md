# ADR 0001 — 하네스 엔지니어링 구조 도입

- 상태: 채택
- 날짜: 2026-09-28

## 맥락

형식상 1~3학년 5인 팀이지만 실제 개발은 튜터 1인이 Claude Code·Codex를 섞어 쓰며 맡고, 8주 안에 배포까지 간다. 튜티는 TIL로 기여한다. 사람 리뷰어가 없으므로 검증을 에이전트와 기계 게이트가 맡아야 한다. 에이전트가 만든 코드가 권한 필터를 빠뜨리거나, 파생 문서가 원본과 어긋나거나, 계층이 뒤엉키면 사람이 전부 잡아내기 어렵다. 또 이 시점에 `requirements.txt`가 설치 불가 상태였는데 아무도 몰랐다. 기계적인 확인 장치가 없었기 때문이다.

## 결정

- 목표 Lv.3. 게이트 1(`make check`, CI)은 모든 변경, 게이트 2(`reviewer` 서브에이전트)는 PR마다, 게이트 3(Codex 교차 리뷰)은 위험 경로 변경 시에만 적용.
- `AGENTS.md`를 도구 공통 지도로 두고, `CLAUDE.md`는 `@AGENTS.md` import와 Claude 전용 메모만 담는다.
- 계층 방향 `api → core → mcp → db`를 AST 기반 구조 테스트로 강제하고, TIL 경로 규칙도 테스트로 강제.
- API 계약 파생물(`docs/generated/openapi.json`)은 결정론적으로 생성하고 스냅샷 테스트로 일치를 확인.
- Python 3.12 고정, `fastapi` 0.115.0 → 0.115.6.

## 결과

- 규칙이 문서에만 있지 않고 CI에서 실패로 드러난다.
- 비용: 1·2학년이 커밋 전에 `make check`를 돌려야 한다. ruff 규칙은 기본값 + import 정렬로 최소화했다.
- 청크 메타데이터 스키마와 DB 마이그레이션 도구는 미정 → 2주차에 ADR 0002로 확정한다.
