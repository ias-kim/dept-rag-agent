# M5 에이전트 루프 · 권한 설계 문서 · 통합 테스트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

- 담당: 김성관 · 시작: 2026-10-27 · 관련 주차: 6주차 (학습일 10/30 목·10/31 금)

**Goal:** `ROUTER_MODE=agent`를 추가해 모델이 권한 필터된 MCP 도구를 스스로 골라 최대 4회 부르고 누적 조각으로 출처 검증된 답을 내게 하고, 권한 설계 문서(1판)·권한 행렬 재검증·로그인→`/api/ask`→화면 출처 통합 테스트로 6주차 문장을 채운다.

**Architecture:** 새 모듈 `backend/app/core/agent.py`가 루프 4요소(① `list_tools` → 모델 `tools` ② `tool_use` → MCP `call_tool` ③ 조각·ID 누적 ④ 종료)를 함수 하나에 드러낸다. `pipeline.answer_question(mode="agent")`는 MCP 연결·임베딩 장애 감시만 맡고 루프에 위임한다. 출처 검증은 기존 `answer.verify_citations`를 누적 조각 전체에 그대로 쓰고, 상한 도달 시 기존 `generate_answer`로 강제 생성한다 — workflow와 같은 검증·생성 코드를 지나야 7주차 비교가 공정하다.

**Tech Stack:** Python 3.12, anthropic 1.8.0 (`beta.messages.create`에 `tools`+`fallbacks` 동시 사용, `BetaToolUseBlock{id,name,input}`, tool_result `{type,tool_use_id,content,is_error}`, `stop_reason`에 `tool_use`·`pause_turn`·`refusal`·`max_tokens` — 설치본에서 확인), mcp 2.2.0 메모리 전송, pytest + anyio, FastAPI TestClient. 새 의존성 없음.

**Spec:** [`docs/design/2026-09-28-system-design.md`](../../design/2026-09-28-system-design.md) §4 권한, §5 에이전트 루프, §6 평가, §8 M5 · 학습계획서 6주차 문장(아래)

## Global Constraints

- Python 3.12, 의존성 `==` 고정, 새 의존성 없음. 계층 `api → core → mcp → db` 역방향 import 금지(`app.core.config`만 예외). `agent.py`는 core라 mcp를 import할 수 있다.
- **도구 상한 `agent_max_tool_calls: int = 4`** (설정값, 이름 있는 상수). 단위는 **실행한 `tool_use` 블록 수**. 상한에 닿은 뒤 남은 블록은 실행하지 않고 강제 생성으로 간다.
- 에이전트 모델 호출은 생성과 같은 인자: `model=generation_model`, `effort=generation_effort`(`output_config`), `max_tokens=generation_max_tokens`, `betas=[FALLBACK_BETA]`, `fallbacks="default"`. 샘플링 파라미터 미사용.
- **모델 입력에 역할·수강 과목을 넣지 않는다.** 권한은 `tools` 목록(MCP `list_tools` 결과 그대로)과 MCP·SQL 겹이 정한다.
- 다음 턴 assistant 메시지는 `response.content`를 **그대로** 넣는다(thinking 블록 포함 — 빼면 API가 400).
- 첫 user 메시지에 `오늘 날짜: YYYY-MM-DD`를 붙인다(workflow와 동일, `deps.today()`).
- 테스트는 실제 Anthropic/OpenAI를 부르지 않는다. 에이전트는 `.env`를 열거나 출력하지 않는다(저장소 `.env`의 키는 무효 — 로컬 실행·평가는 셸 프로필 환경변수 키를 쓰고, pydantic-settings는 환경변수를 `.env`보다 우선한다).
- 공지 코드 2개 신설: `tool_limit_reached`, `invalid_tool_call`. 화면에는 보이지 않게 `frontend/src/notices.js` LABELS에 넣지 않고 주석의 코드 원천 목록에만 추가.
- 개발자 문서: `docs/dev-notes/agent.md` 신설(개념 → 흐름 → 실패 모드 → 다음 수정 → 주의점, 불변 조건 표). 주석은 "왜"와 "깨지면 생기는 일"만.
- 커밋: 한국어 conventional + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 브랜치 `feat/m5-agent`(main에서). 각 태스크 끝에 `make check`(DB: `make db-up`, 포트 5433).
- 게이트: 2(reviewer 서브에이전트) 필수. 게이트 3(Codex)은 위험 경로(`backend/app/mcp/`·`db/`·`api/`)를 건드리면 필수 — 이 계획은 원칙상 건드리지 않지만, 에이전트가 도구에 닿는 새 경로라 **게이트 3도 실행**한다.

## Review Focus

1. **에이전트가 만든 query가 도구 안에서 처음 임베딩되다 공급사 장애** — MCP가 `isError`로 삼키면 "자료 없음" 답이 나가고 한도만 깎인다. 기대: 원래 예외가 `answer_question` 밖으로 올라가 API가 503 + 한도 환불 → Task 2 `test_agent_embedding_failure_surfaces`.
2. **앞선 호출의 조각을 인용한 최종 답** — top-k로 자르면 정상 인용이 `invalid_citation`이 된다. 기대: 누적 조각 전체로 검증 → Task 1 `test_agent_citation_from_earlier_call_is_valid`.
3. **게스트에게 모델이 `search_major`를 부르거나 수강생이 `course_code`로 남의 과목을 요청** — 기대: 전공 조각 0건. 숨은 도구는 MCP 호출 없이 `invalid_tool_call`(장애 공지 `tool_error:` 아님) → Task 2 `test_agent_invalid_call_is_not_executed`. 남의 `course_code`는 MCP가 수강 과목과의 교집합으로 좁혀 "검색 결과 없음"(공지 없음) → Task 3 행렬.
4. **한 응답에 tool_use 블록이 5개** — 기대: 4개만 실행, 5번째는 미실행, 누적 조각으로 강제 생성 + `tool_limit_reached` → Task 2 `test_agent_cap_counts_blocks_not_turns`.
5. **도구 없이 바로 답한 범위 밖 질문** — 기대: 출처 없이 "제공된 자료에서 답을 찾을 수 없습니다."면 `citation_ok=True`(none 지표 통과), 근거 없는 주장이면 `no_citation` → Task 2 `test_agent_direct_answer_without_tools`.

### Task 1: 에이전트 루프 정상 경로 (core)

**Files:**
- Create: `backend/app/core/agent.py`, `backend/app/core/prompts/agent.md`, `backend/tests/db/test_agent.py`
- Modify: `backend/app/core/answer.py`, `backend/app/core/pipeline.py`, `backend/app/core/config.py`, `backend/tests/fakes.py`

**Interfaces:**
- Produces:
  - `answer.render_chunks(hits: Sequence[ChunkHit]) -> str` — `[C{id}] ({source} p.{page}[ {section}])\n{text}` 블록을 빈 줄로 잇는다. `render_context`는 이것을 써서 기존 출력과 바이트 단위로 같게 유지.
  - `Answer.tools_called: list[str] = field(default_factory=list)` — 실행된 도구 이름(순서대로, 미실행 블록 제외).
  - `agent.to_model_tool(tool: mcp.types.Tool) -> dict` → `{"name", "description", "input_schema"}`
  - `agent.agent_prompt() -> str`, `agent.agent_prompt_hash() -> str` (sha256 앞 12자, `prompt_hash`와 같은 방식)
  - `agent.TOOL_LIMIT_REACHED = "tool_limit_reached"`, `agent.INVALID_TOOL_CALL = "invalid_tool_call"`
  - `async def run_agent(question: str, client: ClientSession, llm: Any, settings: Settings, *, today: date, check_upstream: Callable[[], None]) -> Answer` — `check_upstream`은 매 `call_tool` 직후 부른다(Task 2에서 의미 부여, Task 1에서는 `lambda: None`).
  - `config.Settings.agent_max_tool_calls: int = 4`, `router_mode` 주석에 `"agent"` 추가
  - `pipeline.MODES = ("baseline", "workflow", "agent")`
  - `tests.fakes`: `FakeLLM(script: Sequence[SimpleNamespace] | None = None, ...)` — script가 있으면 `beta.messages.create` 호출마다 다음 응답을 순서대로 돌려주고 호출 kwargs를 `calls`에 기록(없으면 기존 동작 그대로). `tool_use_reply(*blocks: tuple[str, str, dict]) -> SimpleNamespace`(각 `(id, name, input)`, thinking 블록 + tool_use 블록들, `stop_reason="tool_use"`), `text_reply(text: str, stop_reason="end_turn") -> SimpleNamespace`(thinking + text).
- 루프 본문(구현자가 쓴다, 순서만 고정):
  1. `tools = [to_model_tool(t) for t in (await client.list_tools()).tools]`, `messages = [{"role": "user", "content": f"오늘 날짜: {today}\n\n질문: {question}"}]`
  2. `response = await anyio.to_thread.run_sync(lambda: llm.beta.messages.create(..., system=agent_prompt(), tools=tools, messages=messages))`
  3. `tool_use` 블록이 없으면 최종 답: 텍스트를 이어 `verify_citations(raw, 누적 전체)` (Task 2에서 refusal·max_tokens·빈 응답 처리 추가)
  4. 있으면 assistant 메시지로 `response.content` 그대로 추가 → 블록마다 `call_tool(name, input)` → `parse_hits` → 누적(`chunk_id` 중복 제거, 높은 점수 유지 — `merge_hits(…, k=len(전체))` 재사용 가능) → tool_result `{"type": "tool_result", "tool_use_id": id, "content": render_chunks(hits) or "검색 결과 없음"}` → 모든 결과를 한 user 메시지로 추가 → 2로.
