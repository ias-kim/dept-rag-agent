# 2026-10-21

## 도서관 열람 창구(웹 화면) 붙이기

- 4주차까지는 개발자가 명령어로 서버를 직접 불러야 질문할 수 있었는데, 5주차에는 학생이 브라우저만 열면 로그인 → 질문 → 답 밑의 "어느 자료 몇 쪽"까지 확인할 수 있는 화면(도서관 열람 창구)을 붙였다는 것을 배움
  - 화면은 React + Vite로 로그인 화면과 질문 화면 두 개를 만듦
  - 서버와 주고받는 코드는 `api.js` 한 파일에만 모음 → 로그인(`/api/auth/login`), 질문(`/api/ask`), 이번 주에 추가한 내 정보(`/api/me`)
  - `/api/me`는 상단에 "AGENT · DB 수강"(게스트는 "게스트 · 학사 자료만") 배지를 보여 주려고 추가함. 수강 과목을 매번 데이터베이스에서 읽어서 수강이 바뀌면 바로 반영되고, 하루 질문 한도는 깎지 않음
- 화면 방향은 목업 세 가지를 같은 질문·실제 답변으로 그려 놓고 비교해서 정했다는 것을 배움

## 소감

지금까지는 명령어로 서버를 불러야만 결과를 볼 수 있어서 개발자만 쓰는 도구 같았는데, 화면이 붙으니 학생이 실제로 쓰는 서비스에 한 걸음 가까워진 느낌이 들었다. 특히 답 밑에 "어느 자료 몇 쪽"이 보이게 한 것이 3주차부터 신경 쓴 출처 검증이 학생 눈에 보이는 결과로 이어진 것 같아 의미 있었다. 서버와 주고받는 코드를 `api.js` 한 파일에 모아 두면 주소나 방식이 바뀌어도 한 곳만 고치면 된다는 점도 좋은 습관이라고 느꼈다. `/api/me`가 단순히 배지를 띄우는 기능처럼 보여도, 수강 정보를 매번 데이터베이스에서 읽고 질문 한도는 깎지 않도록 해야 한다는 점에서 작은 기능도 세심하게 설계해야 한다는 것을 배웠다. 또 화면 방향을 감으로 고르지 않고 같은 질문과 실제 답변으로 목업 세 가지를 비교해서 정한 방식이 4주차에 같은 조건으로 측정을 비교했던 것과 닮았다고 생각했다. 다음에는 실제 학생이 화면을 써 보고 어디서 헷갈리는지 직접 확인해 보고 싶다.
