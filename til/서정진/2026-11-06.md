## 1. 오늘 배운 것

- 지금까지 튜터 컴퓨터 안에서만 열려 있던 도서관을 인터넷에서 빌린 건물(AWS EC2)로 옮기고, 학교 밖에서도 주소(`https://54-180-180-225.sslip.io`)로 찾아올 수 있게 문을 열었다는 것을 배움
  - 문을 연다는 건 곧 아무나 찾아올 수 있다는 뜻이라, "어느 문을 열고 어느 문을 닫을지"를 정하는 게 서버를 띄우는 것보다 더 중요했음
- 5주차에 만든 Docker 이미지는 그대로 쓰고, 실행 구성만 운영용(`docker/docker-compose.prod.yml`)으로 따로 둔 이유를 배움

  | 항목 | 내 컴퓨터용 | 운영용 |
  |---|---|---|
  | DB 포트 | 5433 공개 | 공개 안 함 — 앱만 내부 네트워크로 접속 |
  | 앱 포트 | 8080 공개 | 공개 안 함 — Caddy만 앱에 접속 |
  | 인터넷 입구 | 없음 | Caddy 80·443 |
  | DB 비밀번호 | 개발용 고정값 | 서버에서 생성한 임의값, 없으면 실행 중단 |
  | 재시작 정책 | 없음 | 서버 재부팅 시 자동 시작(`unless-stopped`) |

- Dockerfile의 멀티 스테이지 빌드를 읽어 봄
  - 1단계(`FROM node:22-alpine AS web`)에서 화면을 빌드하고, 2단계에는 `COPY --from=web /web/dist ...`로 결과물만 가져옴 → 책을 제본하는 작업실 도구까지 열람실에 들여놓지 않는 것
  - `USER app` → 일반 사용자로 실행해서 앱이 뚫려도 컨테이너 안에서 관리자 권한을 갖지 못함
  - `alembic ... upgrade head` → 서버가 뜨기 전에 DB 표 구조를 맞춰서 빈 서버 DB에서도 바로 시작 가능
  - `--workers 1` → 로그인 시도 횟수가 프로세스 메모리에 있어서 워커가 늘면 로그인 제한도 그 배수로 풀림
- 입구는 Caddy 하나로 두는 구조를 배움
  - Caddy: 인터넷 요청을 받아 앱으로 넘겨 주는 리버스 프록시. HTTPS 인증서(Let's Encrypt)도 자동으로 받고 갱신함
  - `ports: ["80:80", "443:443"]`는 caddy에만 있고 db·app에는 `ports`가 없음 → 인터넷에서 앱과 DB로 바로 들어갈 길이 없음
  - `FORWARDED_ALLOW_IPS: 172.30.0.10` + Caddy의 `ipv4_address: 172.30.0.10` → 앱은 Caddy가 전한 접속자 IP만 믿음. 어긋나면 모든 사용자가 한 IP로 보여 로그인 제한에 함께 막히거나, 위조 헤더로 제한을 우회당함
  - `${DB_PASSWORD:?}` → 값이 없으면 실행을 멈춰서 빈 비밀번호로 서버가 뜨는 사고를 막음
- AWS 자원은 CloudFormation 설계도(`infra/stack.yaml`) 한 장으로 만든다는 것을 배움
  - 학교 공용 계정이라 다른 학생 자원과 섞이면 안 됨 → 설계도로 만들고 스택 삭제로 내 자원만 정확히 지울 수 있음
  - 보안 그룹: 80·443만 `0.0.0.0/0`(인터넷 전체), 22(서버 관리)는 `!Ref AdminCidr`로 관리자 IP만. 5432·8000은 규칙이 없으니 닫혀 있음
  - `ImageId: !Ref ImageId` → 서버 이미지를 고정. 최신값을 쓰면 스택 갱신 때 서버가 교체되어 DB가 사라질 수 있음
  - `HttpPutResponseHopLimit: 1` → 서버 권한 정보를 서버 자신만 읽게 해서, 컨테이너가 뚫려도 서버 권한을 못 가져감
- 배포 스크립트(`infra/deploy.sh`)에서 비밀값을 다루는 방식을 배움
  - `git archive HEAD` → 작업 중 파일이 아니라 커밋을 올려서 무엇이 배포됐는지 커밋 번호로 말할 수 있음
  - `if [ ! -f .env ]` → `.env`가 이미 있으면 덮어쓰지 않음. DB 비밀번호가 바뀌면 DB 접속이 끊기고, 서명 키가 바뀌면 전원이 로그아웃됨
  - `umask 077` → 새 파일을 소유자만 읽게 만듦
- 색인은 새로 임베딩하지 않고 로컬 DB의 문서 133개·조각 3,727개를 서버로 복사함 → 비용이 없고 평가 때와 같은 색인. 로컬 시험 계정은 옮기지 않음(공개 서버에서 시험 계정이 살아나면 안 되기 때문)
- 운영 설정의 약속은 문서로만 두면 다음 수정 때 깨지기 쉬워서, 설정 파일을 읽어 검사하는 테스트 8개로 고정했다는 것을 배움 (입구는 Caddy뿐, 앱은 Caddy가 전한 IP만 믿음, 22번은 관리자 IP만 등)

## 3. 해결책 또는 시도한 것

- 서버 로그를 따라가니 `credit balance is too low`가 있었고, 원인은 코드나 배포가 아니라 AI 서비스(Anthropic) 크레딧 부족이었음
  - 질문 분류를 위해 AI를 처음 부르는 단계에서 거절됐고, 임베딩용 OpenAI는 정상이었음
  - 5주차에도 "서버에 연결할 수 없습니다" 문구 때문에 원인을 엉뚱한 데서 찾았는데, 이번에도 화면 문구만으로는 원인을 알 수 없어서 로그를 먼저 봐야 한다는 걸 다시 확인함
  - 이 오류는 한도 환불 처리 대상이 아니라서 답을 못 받아도 질문 한도가 깎이는 결함도 같이 발견함 → 원인에 맞는 안내를 보여 주고 한도를 되돌리도록 수정하기로 함
- 접속자 IP 문제는 "앱 입장에서는 모든 요청이 Caddy에서 오니까, Caddy가 적어 준 진짜 접속자 IP를 믿어야 하는데 아무나 적은 값은 믿으면 안 된다"로 정리하니 이해됨. 그래서 믿을 주소를 Caddy 고정 주소 하나로 정하고, 자동 테스트가 두 값이 같은지 검사함
- 스택·compose 파일을 직접 읽으면서 열린 문이 80·443(Caddy)과 22(관리자 IP만)뿐이고, DB 5432·앱 8000은 규칙 자체가 없어서 닫혀 있다는 걸 짚어 봄
- 전문 용어 문제는 임베딩이 문장 전체의 뜻을 숫자로 바꾸기 때문에, 드문 용어 하나보다 문장의 일반적인 의미에 끌려간다고 이해함. 그래서 단어 검색 + 의미 검색(하이브리드)과 중복 조각 정리를 다음 개선 후보로 두고, 효과는 2차 측정으로 확인하기 전까지 "개선됐다"고 쓰지 않기로 함
- 외부 접속 화면 캡처(수강생 외래키 / 게스트 외래키 / 게스트 일본어 특강)는 크레딧 문제 해결 후 휴대폰으로 학교 밖 인터넷에서 진행할 예정
