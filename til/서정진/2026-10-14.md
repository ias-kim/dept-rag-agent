  - 질문을 `academic`(학사·공지) / `major`(전공 강의 내용) / `both`(둘 다) / `none`(학교·학과와 무관) 네 종류로 분류

  - 네 단어가 아닌 출력이 나오면 답을 놓치지 않게 `both`로 처리하지만, 점수를 잴 때는 오답으로 셈 → 엉뚱한 출력을 정답으로 세면 분류 정확도가 부풀려지기 때문
- AI는 질문 종류만 고르고, 어떤 도구를 열지는 프로그램의 처리 표(`plan`)가 정한다는 것을 배움
  - `is_enrolled = bool(user.courses)`는 서버가 데이터베이스에서 꺼낸 값이라 "나 수강생이야" 같은 질문 문장으로 바꿀 수 없음 (3주차 `allowed_courses`와 같은 원리)
  - 수강 과목이 없는데 `major`로 분류되면 도구를 열지 않고 "수강생 전용 자료" 안내만 남김
  - `none`이면 검색도 답변 작성도 하지 않고 "범위 밖" 안내로 끝남
  - 결과는 `Plan(열 도구, 안내)`라는 `frozen=True` dataclass로 돌려줌 → 만든 뒤 바뀌면 안 되는 결정이라서
- 처리 표가 실수해도 권한 관문 두 겹은 그대로라는 것을 확인함

  - `planned_tools is None`이면 기준선(baseline) 방식이라 보이는 도구를 전부 호출 → 같은 코드로 두 방식을 돌려서 다른 차이가 끼어들지 않음

## 2. 어려웠던 것

- 라우터를 붙였더니 점수가 91.7%에서 86.1%로 오히려 떨어져서, 처음엔 라우터를 붙인 것 자체가 잘못된 결정인지 헷갈렸음

- 헷갈리는 질문을 직접 만들어 보는 실습에서 "DB 과제 마감 공지 있어?"가 전공 질문인지 학사 질문인지 스스로도 바로 답하지 못했음

## 3. 해결책 또는 시도한 것

- 틀린 분류 10개를 "손해 있음/없음"으로 나눠 채점해 보니 실제 손해는 1개였고, 점수 하락의 원인이 `none` 오분류 하나라는 게 드러남
- 잘못 안내했을 때의 손해가 비대칭이라는 점으로 정리하니 지시문 보완 방향이 이해됨
  - `none`으로 잘못 보내면 답을 잃지만, `academic`으로 잘못 보내면 도구를 한 번 더 들르는 것뿐
  - 그래서 `none`은 학교·학과와 명백히 무관할 때만 쓰고, 과목 이름이 있어도 시간·강의실·신청·출석을 묻는 질문은 학사로 분류하도록 고침
  - 시험지 문항에 맞춘 문장은 넣지 않고 원칙만 넣음 → 시험지에만 맞춘 규칙은 실제 질문에서 무너지기 때문
- "자료 밖" 질문 문제는 라우터가 도서관에 어떤 자료가 있는지 모르기 때문에 의미상 학사인 질문을 학사로 보는 게 자연스럽다고 정리함. 2차에서 자료가 있는 질문은 30/30(100%)으로 분류했고 틀린 5개는 모두 자료 밖 질문이었음
- 헷갈리는 질문은 질문 → 분류 → 처리 표 → 도구 → 답변 흐름을 순서대로 따라가며 각 단계에서 무엇이 결정되는지 확인함. 애매하면 `none`만 피하면 되고, 학사·전공 중 어느 쪽으로 가도 `both`나 관문①이 받쳐 준다는 점을 코드에서 확인함
