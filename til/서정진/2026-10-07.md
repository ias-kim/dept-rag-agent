# 2026-10-07 TIL

## 1. 오늘 배운 것

- 2주차에 채운 색인 2종을 AI가 부를 수 있는 MCP 도구 2종으로 만든다는 것을 배움
  - `search_academic`: 학사 규정·일정·공지 검색 (전체 공개)
  - `search_major`: 전공 강의자료 검색 (수강생 한정)
- 1주차에 말로만 들었던 권한 관문 두 겹이 도구 코드에서 실제로 어떻게 동작하는지 확인함
  - 관문①: `if user.courses:`일 때만 `search_major`를 목록에 더함 → 수강 과목이 없으면 AI는 전공 도구가 있는지조차 모름
  - 관문②: 도구 안에서 자료를 꺼낼 때 2주차에 만든 권한 조건이 들어간 조회문을 그대로 사용함
- 과목 인자는 범위를 "좁히기만" 할 수 있다는 것을 배움
  - `allowed = user.courses & {str(requested).upper()} if requested else user.courses`
  - `&`(교집합) 때문에 수강하지 않는 과목 코드를 넘기면 결과가 비어 검색 결과도 비어 나옴
  - `user.courses`는 AI가 만든 값이 아니라 서버가 데이터베이스에서 꺼낸 값이라는 점이 핵심
- 라우터가 붙기 전에는 도구 설명문(description)이 AI가 도구를 고르는 유일한 단서라서, "수강신청·성적·졸업·장학·휴학·일정"처럼 질문 유형 단어로 적어야 한다는 것을 배움
- 출처는 AI가 쓰지 않고 코드가 조립한다는 것을 배움
  - 찾아온 조각마다 번호표를 붙이고 AI는 답에 `[C12]`처럼 번호만 적음
  - 파일명·쪽은 코드가 조각 꼬리표에서 만들어 붙이고, 검색되지 않은 번호는 지워서 AI가 출처를 지어내도 화면에 나오지 않음
- 라우터 없는 기준선(baseline)을 먼저 재야 4주차에 라우터를 붙였을 때 "진짜 올랐다"고 말할 수 있다는 것을 배움
  - 보이는 도구를 모두 호출해 점수 높은 순 5개(Top-k, k=5)를 모아 답변 생성
- 평가셋 36문항(전공 15·학사 12·두 영역 3·자료 밖 6)을 작성하고 sha256 지문으로 동결함 → 이후 문항을 고치면 검사가 실패함
- 평가를 하나로 뭉치지 않고 4종으로 나눠야 틀렸을 때 어느 단계가 원인인지 알 수 있다는 것을 배움
  - 검색 정확도(recall@5) 27/30 = 90.0%
  - 출처 일치 27/30 = 90.0%
  - 답변 정확도 33/36 = 91.7%
  - 자료 밖 질문 처리 6/6 = 100%
  - 응답 시간 중앙값 2.38초

## 2. 어려웠던 것

- 평가 문항으로 도구를 테스트할 때 무엇부터 확인해야 맞는 방법인지 몰라 헤맸음
- 틀린 3문항(M08·M10·M11)이 모두 전공 문항이었는데, 처음엔 답변을 잘못 만든 건지 검색을 못 한 건지 구분이 안 됐음
- M08은 개념 설명은 했지만 구문이 빠져 있어서 정답으로 볼지 오답으로 볼지 애매했음

## 3. 해결책 또는 시도한 것

- 튜터와 함께 문항마다 정답 출처가 실제 색인에 있는지 먼저 확인하고, 정답 쪽 검색 → 출처 일치 → 답변 정확도 순서로 나눠서 보는 방식으로 진행함
- 지표를 나눠서 보니 세 문항 모두 답변 생성이 아니라 검색 단계에서 이미 정답 쪽을 놓친 경우라는 게 드러남 (M10·M11은 "찾을 수 없다"고 답해서 틀린 사실 주장은 없었음)
- M08은 핵심 사실이 빠졌다고 보아 오답으로 채점하고, 이 기준을 채점 기준 문서에 기록해 4주차에도 같은 기준으로 채점하기로 함
- 2주차에 남긴 질문(50자 미만 짧은 조각이 검색 품질을 떨어뜨리는가)은 틀린 3문항만으로는 결론 낼 수 없어서 7주차 재측정 때 다시 보기로 함
