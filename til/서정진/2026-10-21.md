## 1. 오늘 배운 것

- 4주차까지는 개발자가 명령어로 서버를 직접 불러야 질문할 수 있었는데, 5주차에는 학생이 브라우저만 열면 로그인 → 질문 → 답 밑의 "어느 자료 몇 쪽"까지 확인할 수 있는 화면(도서관 열람 창구)을 붙였다는 것을 배움
  - 화면은 React + Vite로 로그인 화면과 질문 화면 두 개를 만듦
  - 서버와 주고받는 코드는 `api.js` 한 파일에만 모음 → 로그인(`/api/auth/login`), 질문(`/api/ask`), 이번 주에 추가한 내 정보(`/api/me`)
  - `/api/me`는 상단에 "AGENT · DB 수강"(게스트는 "게스트 · 학사 자료만") 배지를 보여 주려고 추가함. 수강 과목을 매번 데이터베이스에서 읽어서 수강이 바뀌면 바로 반영되고, 하루 질문 한도는 깎지 않음
- 화면 방향은 목업 세 가지를 같은 질문·실제 답변으로 그려 놓고 비교해서 정했다는 것을 배움

  | 목업 | 모양 | 판단 |
  |---|---|---|
  | A. 채팅형 | 질문 말풍선 + 답 카드 | 익숙하지만 처음 온 학생에게 무엇을 물어야 하는지 알려 주지 못함 |
  | B. 검색형 (선택) | 큰 제목·한 줄 설명·검색창·예시 질문, 답 아래 근거 자료 목록 | 서비스 설명과 출처를 가장 분명하게 보여 줌 |
  | C. 2단 문서형 | 왼쪽 답, 오른쪽 근거 자료 패널 | 대조에는 좋지만 원문 미리보기 등 서버 기능이 더 필요함 |

- 로그인 출입증(토큰)을 다루는 방식에도 이유가 있다는 것을 배움
  - 서버가 12시간짜리 토큰을 주고, 화면은 요청마다 함께 보냄
  - 토큰은 탭을 닫으면 사라지는 `sessionStorage`에만 보관 → 학교 공용 PC에서 다음 사람이 로그인된 채로 쓰지 않게
  - 만료되었으면 화면을 여는 즉시 로그인 화면으로 보내고 "로그인이 만료되었습니다" 안내 → 질문을 다 쓴 뒤에 튕겨서 입력이 사라지지 않게
  - 답을 기다리는 동안 회색 자리표시(스켈레톤)를 보여 주고 다시 보내지 못하게 막음 → 하루 질문 한도가 헛되이 깎이지 않게. 한글 조합 중의 Enter는 무시
- 근거 출처 표시는 2주차부터 이어진 흐름의 끝이라는 것을 배움
  - 2주차에 조각마다 붙인 꼬리표(파일·쪽·절) → 3주차에 프로그램이 출처로 조립 → 5주차에 화면이 "이 답변의 근거 자료" 목록으로 표시
  - 답 본문의 `[1]`·`[2]`는 같은 번호의 파란 배지로 바뀌고, 목록 한 줄에는 번호 · PDF 표시 · 파일명 · 절 제목 · "4쪽"이 보임
- 근거 자료 목록 코드(`frontend/src/AskPage.jsx`의 `SourceList`)에서 번호를 화면이 새로 매기지 않는 것이 핵심이라는 것을 배움

  ```jsx
  function SourceList({ sources }) {
    if (sources.length === 0) return null
    return (
      <section className="sources">
        <h2>이 답변의 근거 자료</h2>
        <ol>
          {sources.map((s, i) => (
            <li key={i} className="source">
              <span className="source-num">{i + 1}</span>
              <span className="pdf">PDF</span>
              <span className="source-text">
                <b title={s.file}>{fileName(s.file)}</b>
                {s.section && <small>{s.section}</small>}
              </span>
              <span className="source-page">{s.page}쪽</span>
            </li>
          ))}
        </ol>
      </section>
    )
  }
  ```

  - `if (sources.length === 0) return null` → 출처가 없는 정상 답(학과와 무관한 질문, 수강생 전용 안내)에서는 칸을 통째로 그리지 않음. 없으면 빈 제목만 남음
  - `sources.map((s, i) => … {i + 1})` → 서버가 본문 인용에 매긴 순서와 `sources` 순서가 같아서 `i + 1`만 붙이면 번호가 맞음. 화면에서 정렬하거나 중복을 지우면 본문 ②가 다른 파일을 가리키게 됨
  - `fileName(s.file)` / `title={s.file}` → 학생에게는 `3-1_mcp.pdf` 같은 파일명만, 전체 경로는 마우스를 올릴 때만 보임
  - `{s.section && <small>…}` → 절 정보가 없는 조각이면 그 줄만 뺌. 없으면 화면에 "null"이 찍힘
- Docker 이미지는 "이삿짐 상자 하나로 포장"하는 단계라는 것을 배움
  - 1단계에서 화면을 빌드하고, 2단계 상자에 서버 코드와 빌드된 화면만 담아 서버가 화면까지 같은 주소에서 내보냄
  - API 키가 든 `.env`와 원본 PDF는 상자에 넣지 않고 실행할 때만 건넴 → 자동 테스트로 검사
  - `make app-up` 한 줄로 화면 + 서버를 띄움 → 7주차에 AWS로 옮길 때 "내 컴퓨터에선 됐는데"가 생기지 않게
- 실습: 같은 질문 "MCP에서 Host, Client, Server는 각각 무슨 역할이야?"를 계정별로 던져 화면을 비교함

  | 계정 | 화면에 보인 것 | 확인한 것 |
  |---|---|---|
  | 수강생 (AGENT·DB) | 상단 "AGENT · DB 수강", 근거 자료 2개 — `3-1_mcp.pdf` 4쪽·11쪽 | 본문 번호 배지 ①·②와 목록 번호 일치 |
  | 게스트 (수강 과목 없음) | 상단 "게스트 · 학사 자료만", 전공 자료 없이 "수강생 전용" 안내 | 1주차부터 지켜 온 열람 권한이 화면에서도 그대로 동작 |
  | 틀린 비밀번호 / 만료된 토큰 | "아이디 또는 비밀번호가 올바르지 않습니다" / 로그인 화면 + "로그인이 만료되었습니다" | 오류마다 알맞은 안내, 만료 시 토큰 삭제 |

  - 수강생 계정 답의 번호 배지를 목록과 대조하고, 실제 `3-1_mcp.pdf`의 4쪽·11쪽을 펼쳐 내용이 답과 맞는지 확인함

## 2. 어려웠던 것

- 개발용 서버에서는 잘 되던 질문이 Docker 상자 안에서는 전부 실패했는데, 화면에 "서버에 연결할 수 없습니다"라고 떠서 처음엔 네트워크나 포트 문제인 줄 알았음
- 게스트 계정으로 전공 질문을 했을 때 안내 띠와 답 본문에 같은 문장이 두 번 나와서, 둘 중 무엇을 빼야 하는지 헷갈렸음
- 번호를 그냥 `i + 1`로 붙이는 코드가 너무 단순해 보여서, 이게 정말 본문 번호와 항상 맞는지 처음엔 확신이 안 섰음

## 3. 해결책 또는 시도한 것

- 상자 실패 원인을 따라가 보니 저장소 `.env`의 AI 서비스 키가 이미 무효였고, 개발용 서버는 컴퓨터에 따로 설정된 다른 키를 쓰고 있어서 그동안 드러나지 않았던 것이었음
  - 서버 내부 오류는 "서버에서 오류가 발생했습니다"로 구분해 보여 주도록 고침 → 학생이 자기 인터넷 문제로 오해하지 않게
  - 배포 전 점검표에 "설정 파일의 API 키·로그인 비밀 키가 실제로 동작하는지 확인"을 넣고, 개발용 서버도 저장소 설정 파일의 키로만 돌도록 맞춤
- 안내 띠 중복은 본문이 이미 같은 말을 하는 경우에만 띠를 생략하는 방식으로 정리됨. 본문에 안내가 없을 때는 띠가 "전공 강의자료는 수강생만 볼 수 있어 답변에서 제외했습니다"를 알려 줘야 하기 때문
- `i + 1` 문제는 서버가 본문 인용을 `[1]`·`[2]`로 매긴 순서 그대로 `sources`를 보낸다는 점을 확인하고 이해함. 화면이 순서를 건드리지 않는 것 자체가 번호를 맞추는 장치이고, 오히려 화면에서 "보기 좋게" 정렬하는 순간 깨진다는 걸 알게 됨
