# 2026-09-17 TIL

## 1. 오늘 배운 것

- 워크플로우와 AI 에이전트는 "다음에 무엇을 할지 누가 정하는가"로 구분된다는 것을 배움
- 우리 서비스가 그리는 흐름: LLM이 사용자의 질문 의도를 분석 → 그 의도에 맞는 도구(전공자료 검색/학사 공지 검색 등)를 선택 → RAG(검색 증강 생성) 방식으로 데이터베이스를 조회해 근거 자료를 가져옴 → 가져온 자료를 조합해 답변을 생성하되, 근거가 부족하면 재시도(재검색)하는 구조
- 즉 "질문 분석 → 도구 선택 → 검색 → 답변 생성" 각 단계가 명확히 나뉘어 있고, 근거가 없으면 바로 답하지 않고 다시 찾아본다는 점이 핵심

## 2. 어려웠던 것

- 권한 관문(permission gate)을 설계할 때, **어떤 자료를 누구에게 보여줘야 하는지**와 **어떤 상황에서 도구 호출 자체를 막아야 하는지**를 구분하는 기준을 세우는 게 어려웠음

## 3. 해결책 또는 시도한 것

- 관련 자료를 검색해보면서, 실제로는 노출되는 도구 목록 자체를 권한별로 다르게 구성하고(권한 없는 도구는 아예 목록에서 안 보이게), 모든 도구는 **읽기(read) 권한만** 부여하며 **쓰기(write)는 애초에 허용하지 않는 것**이 일반적인 접근이라는 걸 확인함

## 4. 느낀점

- 조사해서 내용을 정리하는 것과, 그걸 다른 사람에게 이해되도록 설명하는 것은 별개의 어려움이라는 걸 느낌
